# Формальное руководство с экранами

Исходный текст — [tools/guide_source.md](../../tools/guide_source.md). Сборщик — [tools/build_guide.py](../../tools/build_guide.py), съёмка реального интерфейса — [tools/capture_guide.js](../../tools/capture_guide.js).

Текст описывает текущие права: группы создают все пользователи, участников добавляет любой участник группы. Ранее сделанные на Рабочем столе снимки могут отражать предыдущие права; для новой версии нужно переснять экраны.

## Зависимости

Для обычного приложения достаточно `requirements.txt`. Только для съёмки и PDF дополнительно требуются:

- Node.js с глобальным `fetch` (проверено на версии 24);
- исполняемый файл `google-chrome` в `PATH`;
- Python-модуль `cairo` из пакета Pycairo и системная библиотека Cairo;
- шрифт Liberation Serif для выбранного макета.

В активированном окружении:

```bash
python -m pip install -r requirements-docs.txt
```

Установка Pycairo может потребовать системных библиотек и средств сборки для вашей ОС. В изолированной среде без права открыть локальный порт или запустить Chrome инструмент съёмки не заработает; его можно запустить в обычном терминале компьютера.

## Снять экраны и собрать руководство

Из корня проекта:

```bash
node tools/capture_guide.js
```

Сценарий создаёт отдельные временные базу и профиль браузера, запускает демонстрационное приложение на свободном порту, проходит экраны и делает 14 снимков. После съёмки вызывает сборщик PDF. Рабочий `testlab.sqlite3` не используется. По завершении временные процессы и каталог очищаются.

Результаты по умолчанию находятся в `docs/user-guide/generated/`:

```text
generated/
├── Скриншоты/                       # 14 PNG
├── Руководство пользователя.pdf
├── Руководство пользователя.md
├── Лист утверждения.pdf
└── build-status.json                 # Страницы, рисунки и сведения о сборке
```

Каталог результата не добавляется в Git автоматически. Так в репозиторий не попадают устаревшие сгенерированные материалы.

## Сохранить в другую папку

Оба инструмента читают `TESTLAB_GUIDE_DIR`:

```bash
TESTLAB_GUIDE_DIR="$HOME/Рабочий стол/ТестЛаб — руководство" node tools/capture_guide.js
```

Это позволяет обновить ранее созданное руководство на Рабочем столе. Переменная не относится к серверу приложения; `TESTLAB_DB` настраивает другой файл — базу данных.

## Пересобрать только текст и PDF

Когда все 14 снимков уже находятся в `Скриншоты/` выбранного каталога:

```bash
python tools/build_guide.py
```

При другом месте вывода задайте тот же `TESTLAB_GUIDE_DIR`. Сборщик требует все снимки и не заменяет отсутствующие изображения макетами.

Документ собирается со структурой руководства оператора ЕСПД: аннотация, содержание, назначение, условия, выполнение, сообщения, перечни и лист изменений. Информация об используемых стандартах находится в исходнике и ссылках сборщика. Лист утверждения оставляет поля организации и подписей для заполнения. Изменение реквизитов, даты и обозначения документа выполняется в `build_guide.py`.
