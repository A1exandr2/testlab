# Проверка проекта

## Команды

Из корня проекта с установленными зависимостями:

```bash
python -m unittest -v test_workflow.py
node --check app.js
node test_ui.js
node --check tools/capture_guide.js
python -m py_compile server.py tools/build_guide.py
```

Для Python-тестов нужен `bcrypt`; для `node test_ui.js` внешние пакеты не требуются. Генератор PDF для запуска API-тестов не нужен.

## API: `test_workflow.py`

Восемь тестов проверяют:

1. Обмен проверками и результатами между независимыми сессиями, метрики и выход.
2. Регистрацию без повышения роли, создание групп обычным аккаунтом, CSRF и недействующие старые маршруты.
3. Изоляцию групп, включая другой аккаунт типа `admin`, и принадлежность проверки группе.
4. Повторную инициализацию без потери данных, дубликатов и сброса пароля.
5. Перенос старых ролей, участия и сохранение старых таблиц и записей.
6. Исправление ошибочно повышенного старого аккаунта и обновление роли в существующей сессии.
7. Полный сценарий обычных пользователей: создать группу, пригласить человека, приглашённому пригласить следующего, добавить проверку, сохранить результат; посторонний доступа не получает.
8. Проверку полей, допустимых результатов, дубликатов и ограничения неверных входов.

Каждый тест создаёт временную SQLite-базу и подменяет `server.DB`, затем восстанавливает значение. Класс `Browser` имитирует отдельные cookie и CSRF-токены и вызывает настоящий `App.dispatch()`.

Эти тесты не поднимают TCP-сервер, не управляют настоящим браузером и не проверяют внешний вид. Поэтому они работают даже в среде, запрещающей открытие локального порта.

## Интерфейс: `test_ui.js`

Node.js загружает реальные функции `app.js` в изолированный контекст со служебной заглушкой `document`. Проверяются поиск, сортировки, фильтр, расчёт/разметка диаграммы, экранирование значений и доступность добавления участников для обычного пользователя.

Это проверка функций и HTML-строк, а не полноценный DOM-тест. Она не проверяет фокус, клики в реальном браузере, размеры элементов и сетевые запросы.

## Ручная проверка после изменений

1. Запустить сервер и зарегистрировать пользователя в обычном окне браузера.
2. Под ним создать группу, убедиться, что роль остаётся «Пользователь».
3. Во втором профиле или приватном окне зарегистрировать другого человека.
4. Первому добавить второго через «Участники»; дождаться появления группы во втором окне.
5. Второму добавить проверку, первому сохранить результат. Убедиться, что оба окна и диаграмма показывают изменение.
6. Проверить поиск, каждый фильтр, сортировку, пустой результат поиска и отмену формы.
7. Под аккаунтом вне группы проверить отсутствие этой группы.
8. Выйти из одного профиля; второй должен продолжить работу.

После изменения Python-кода перезапустите сервер. Обновление только страницы может загрузить новый JavaScript при старом API в памяти.

## Съёмка экранов

`node tools/capture_guide.js` проходит реальные экраны в отдельной базе, делает 14 снимков и запускает сборщик PDF. Это дополнительная проверка пользовательского маршрута. Зависимости и ограничения описаны в [user-guide/README.md](user-guide/README.md).
