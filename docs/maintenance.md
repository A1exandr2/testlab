# Сопровождение и передача проекта

## Что хранится в репозитории

В поставку входят исходники, SQL-схема, тесты, документация и инструменты её сборки. После клонирования приложение создаёт собственную новую базу.

Исключены через `.gitignore`:

- `*.sqlite3`, `*.sqlite3-wal`, `*.sqlite3-shm` и каталог `backups/`;
- виртуальные окружения, кэши Python, `.env` и локальные служебные каталоги;
- прежний машинный отчёт `tools/guide_status.json`;
- заново создаваемое руководство в `docs/user-guide/generated/`;
- пакеты передачи `*.bundle` и `dist/`.

Файл `requirements.txt` описывает запуск приложения; `requirements-docs.txt` добавляет Pycairo для PDF. Данные реальных пользователей не требуются для демонстрации: начальные записи создаются при запуске, а инструмент съёмки использует собственную временную базу.

## Резервная копия SQLite

Для копирования работающей базы используйте SQLite Backup API. Пример из корня проекта:

```bash
python3 - <<'PY'
import sqlite3
from contextlib import closing
from datetime import datetime
from pathlib import Path

source = Path('testlab.sqlite3').resolve()
folder = Path('backups')
folder.mkdir(exist_ok=True)
target = folder / (datetime.now().strftime('%Y%m%d-%H%M%S') + '.sqlite3')
with closing(sqlite3.connect(f'file:{source}?mode=ro', uri=True)) as src:
    with closing(sqlite3.connect(target)) as dst:
        src.backup(dst)
print(target)
PY
```

Если используется `TESTLAB_DB`, укажите фактический путь источника. Режим `mode=ro` не создаёт пустой файл при ошибке пути. При WAL не следует считать простое копирование одного активного файла базы согласованной резервной копией.

Для восстановления остановите сервер и остальные процессы, работающие с этой базой. Сохраните текущий набор файлов отдельно, восстановите согласованную копию и запустите приложение с нужным `TESTLAB_DB`. Не смешивайте восстановленный файл со старыми служебными файлами WAL/SHM.

Для чистой демонстрации проще выбрать новый путь `TESTLAB_DB`, чем удалять рабочую базу.

## Изменение кода и структуры

- После изменений `server.py` или схемы требуется перезапуск процесса.
- `schema.sql` определяет структуру новой базы. Для добавления столбца в существующую базу нужен явный перенос.
- Перед переносом сохраните резервную копию.
- Однократные действия фиксируются в `app_settings`; существующие отметки не удаляются ради повторного запуска.
- Сервер раздаёт статические файлы с диска, поэтому новый интерфейс может появиться раньше перезапуска API.
- Обычные HTTP-запросы журналируются стандартным обработчиком в терминал. Отдельного постоянного журнала действий в текущем интерфейсе нет.

## Текущие ограничения

Приложение предназначено для локальной совместной демонстрации и ручных проверок. В нём нет автоматического запуска тестов проекта, редактирования и удаления созданных проверок, восстановления пароля, вложений, почтовых уведомлений и отдельного экрана истории результатов. Сами результаты в базе сохраняются.

Состояние передаётся целиком, отдельной пагинации нет. API-запросы сериализуются одним процессом. Синхронизация — опрос раз в три секунды; при одновременном сохранении текущим становится последний результат. Ограничение неудачных входов хранится в памяти.

Сервер использует обычный HTTP и стандартный `http.server`. В нём нет встроенной настройки HTTPS, cookie `Secure`, внешнего управления секретами или готовой схемы промышленного размещения. Демонстрационный пароль известен из исходников; изменение константы не меняет пароль уже созданного аккаунта. Сетевое размещение требует отдельной подготовки приложения и окружения.

## Публикация на GitHub

Подготовленный проект можно опубликовать приватно. Через GitHub CLI из обычного терминала с доступом к GitHub:

```bash
gh auth login
gh repo create testlab --private --source=. --remote=origin --push
```

Команда `repo create` предполагает уже созданный локальный коммит и отсутствие `origin`. Если репозиторий с таким именем уже существует, используйте другое свободное имя либо настройте существующий remote осознанно. Не выполняйте force push в чужую историю.

Если доступна только переносимая копия `testlab-source.bundle`, сначала получите полноценный локальный репозиторий:

```bash
git clone /путь/к/testlab-source.bundle testlab-git
cd testlab-git
gh auth login
gh repo create testlab --private --source=. --remote=origin --push
```

Bundle содержит Git-историю и исходники на момент его создания, но не заменяет удалённый репозиторий. После дальнейших изменений нужна новая фиксация и обычный `git push` из рабочего Git-клона.
