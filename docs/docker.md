# Docker и Makefile

Нужны Docker Engine с Compose v2 или новее и GNU Make. Локальная установка Python, Node.js, Java и GraalVM не требуется. Все команды выполняются из корня проекта.

Сборка принимает стандартные `HTTP_PROXY`, `HTTPS_PROXY` и `NO_PROXY`. На Linux Makefile использует сеть хоста только на этапе сборки, чтобы был доступен в том числе локальный прокси. Для обычной изолированной сети сборки: `make BUILD_NETWORK=default`. Сеть работающего приложения остаётся отдельной сетью Compose.

```bash
make                   # сборка и запуск, ожидание готовности
make stop              # остановить
make up                # запустить снова
make restart           # пересобрать и перезапустить
make down              # удалить контейнеры и сеть, сохранить базу
make help              # все команды
```

Адрес: http://127.0.0.1:8765. Начальный вход: `admin@testlab.local` / `Admin12345!`. При первом запуске в новом томе создаётся новая база. Корневой `testlab.sqlite3` автоматически не переносится.

Если порт занят: `make up PORT=18765`. Этот же параметр нужен при следующем запуске или перезапуске. `PROJECT=другое-имя` создаёт независимый экземпляр с собственным томом; для одновременной работы нужен другой порт.

## Две среды

По умолчанию используется CPython 3.14 на Alpine. В рабочий образ входят только сервер, интерфейс, SQL-схема, команды управления и bcrypt. Word-отчёт, рабочая база, исходные образцы, Git, локальные настройки и тесты в него не копируются. Node.js и средства сборки также остаются вне рабочего образа.

```bash
make graal                    # переключить приложение на GraalPy
make RUNTIME=graalpy test-py   # проверить Python-код на GraalPy
make up                       # вернуться на CPython
make compare                  # собрать обе среды и показать размеры
```

GraalPy 25.4.4 Community - Python-среда проекта GraalVM. Используется нативная сборка интерпретатора без отдельной JVM. Это не преобразование кода приложения в самостоятельный исполняемый файл. Пакет bcrypt устанавливается через pip самой GraalPy из совместимого wheel. Архив интерпретатора проверяется по SHA-256; предусмотрены amd64 и arm64. Проверка проекта выполнена на amd64.

GraalPy требует больше места, чем CPython для этого приложения. Поэтому компактный вариант выбран основным. Переключение среды сохраняет тот же том SQLite. Источники: [официальный релиз GraalPy](https://github.com/oracle/graalpython/releases/tag/graal-25.4.4), [документация GraalPy](https://www.graalvm.org/python/docs/).

Замер 28.10.2026 на Linux amd64, Docker 29.7: `DISK USAGE` рабочего образа CPython около 75 МБ, GraalPy около 537 МБ. Память контейнера в простое: примерно 16 и 146 МБ соответственно. Это наблюдения на данной машине, а не фиксированные требования. На обеих средах прошли 16 Python-тестов; отдельно прошли JavaScript-тесты интерфейса. Проверены также готовность контейнера, остановка и запуск с сохранением базы, резервное копирование и восстановление в отдельный том.

## Состояние и место

```bash
make status        # контейнер, фактический образ, порт, состояние
make health        # HTTP и доступ к SQLite; код ошибки, если не готов
make logs          # последние 100 строк
make follow        # непрерывные логи, выход Ctrl+C
make stats         # CPU, память, сеть и дисковый ввод-вывод
make size          # образы проекта и размеры файлов базы
make docker-size   # место всех объектов Docker, включая кэш сборки
```

В новых версиях Docker `DISK USAGE` показывает размер с распакованными слоями, `CONTENT SIZE` - размер содержимого образа. Общие слои учитываются в нескольких образах, поэтому складывать строки нельзя. Сборочный кэш, тестовые образы, база и резервные копии занимают дополнительное место. Команды не очищают другие проекты Docker.

Контейнер работает от UID 10001, корневая файловая система доступна только для чтения. Запись разрешена в `/data` и временный `/tmp`. Порт открыт только на localhost. По умолчанию лимиты составляют 512 МБ памяти и 1 CPU; изменить: `make up MEMORY_LIMIT=1g CPU_LIMIT=2`. Логи ограничены двумя файлами по 5 МБ.

## Данные и копии

```bash
make db            # количество записей в каждой таблице и проверка целостности
make tables        # названия таблиц и SQL создания
make query SQL="SELECT id,name,email FROM users"
make backup        # сохранить согласованную копию в backups/
```

`query` открывает SQLite только для чтения и выводит максимум 100 строк. Просмотр базы и копирование работают также при остановленном сервере. Резервная копия создаётся через SQLite Backup API, в том числе при работающем сервере и наличии WAL. Папка `backups/` исключена из Git.

База находится в томе `testlab_data` (`<PROJECT>_data` при другом имени), внутри контейнера - `/data/testlab.sqlite3`. Остановка, пересоздание контейнера и `make down` сохраняют том. Команды удаления тома в Makefile нет.

Восстановление выполняется в пустой том, чтобы случайно не заменить рабочие данные:

```bash
make PROJECT=testlab-restored build
make PROJECT=testlab-restored import-db FILE=backups/имя-копии.sqlite3
make PROJECT=testlab-restored PORT=18766 up
```

Импорт проверяет целостность SQLite и наличие семи таблиц ТестЛаб. Существующая база не заменяется. Для переноса старой локальной базы сначала остановите локальный сервер и используйте её как `FILE` для пустого тома. Если сервер продолжает работу, сначала создайте согласованную копию через SQLite Backup API, а не копированием одного файла при наличии WAL.

## Тесты

```bash
make test                     # Python и JavaScript в отдельных образах
make RUNTIME=graalpy test-py   # те же Python-сценарии в GraalPy
```

Тесты используют временные базы. Рабочий том к тестовым контейнерам не подключается.
