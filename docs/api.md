# HTTP API

API обслуживается тем же `server.py`, что и интерфейс. Базовый адрес стандартного запуска — `http://127.0.0.1:8765/api/`. Запросы и ответы используют JSON. Все успешные операции ниже возвращают HTTP `200`.

## Общие правила

- Для POST нужен `Content-Type: application/json`; тело — объект JSON, не массив.
- Размер тела ограничен 200 000 байтами.
- Для авторизованного доступа передаётся cookie `testlab_session`.
- Для каждого POST, кроме `register` и `login`, нужен заголовок `X-CSRF-Token` из ответа входа или `/api/me`.
- Если браузер прислал `Origin`, сервер сравнивает его с `http://` + `Host`.
- Обязательные и необязательные строковые поля обрабатываются через `strip()`. Это относится и к паролю при регистрации/входе.
- Дополнительное поле `role` в запросе регистрации не выдаёт права администратора.

## Список маршрутов

| Метод | Путь | Авторизация | Назначение |
| --- | --- | --- | --- |
| POST | `/api/register` | Нет | Создать аккаунт и сессию. |
| POST | `/api/login` | Нет | Войти в существующий аккаунт. |
| GET | `/api/me` | Cookie | Получить аккаунт и CSRF-токен. |
| GET | `/api/state?project=ID` | Cookie | Получить группы и состояние выбранной группы. |
| POST | `/api/logout` | Cookie + CSRF | Завершить текущую сессию. |
| POST | `/api/projects` | Cookie + CSRF | Создать группу и добавить её создателя. |
| POST | `/api/members` | Cookie + CSRF | Добавить человека в группу, где вызывающий состоит. |
| POST | `/api/checks` | Cookie + CSRF | Добавить проверку в свою группу. |
| POST | `/api/checks/result` | Cookie + CSRF | Сохранить результат проверки своей группы. |

Старые маршруты требований, планов, кейсов, прогонов и дефектов не обслуживаются. Для текущих проверок используются именно `/checks` и `/checks/result`.

## Регистрация и вход

`POST /api/register`:

```json
{
  "name": "Анна",
  "email": "anna@example.test",
  "password": "User12345!"
}
```

`name` — до 80 символов; `email` — до 254, с проверкой формы адреса. Пароль — минимум 10 символов и максимум 72 байта в UTF-8 после удаления краевых пробелов. Почта уникальна и сохраняется в нижнем регистре. Новому аккаунту назначается `user`.

`POST /api/login` принимает `email` и `password`. Оба действия возвращают одинаковую структуру:

```json
{
  "user": {"id": 2, "name": "Анна", "email": "anna@example.test", "role": "user"},
  "csrf": "значение-токена"
}
```

Дополнительно устанавливается cookie `testlab_session`. После пяти неверных входов по одной почте новые попытки получают `429` в течение пяти минут. Счётчик не сохраняется между перезапусками сервера.

`GET /api/me` возвращает `user` и `csrf` для действующей сессии.

## Получение состояния

`GET /api/state` без параметра выбирает первую доступную группу из списка, упорядоченного SQL-запросом по названию и номеру. `GET /api/state?project=3` выбирает указанную группу с проверкой участия.

Пример сокращённого по числу записей, но полного по полям ответа:

```json
{
  "user": {"id": 2, "name": "Анна", "email": "anna@example.test", "role": "user"},
  "projects": [{"id": 3, "name": "Моя группа"}],
  "project_id": 3,
  "project_role": "member",
  "users": [
    {"id": 2, "name": "Анна", "email": "anna@example.test", "role": "member", "joined_at": "2026-10-28T10:00:00+00:00"}
  ],
  "checks": [
    {
      "id": 8,
      "title": "Вход пользователя",
      "steps": "Ввести верные данные и нажать «Войти»",
      "expected": "Открылся обзор",
      "preconditions": "",
      "created_at": "2026-10-28T10:01:00+00:00",
      "creator": "Анна",
      "status": "not_run",
      "actual": "",
      "updated_at": null,
      "updated_by": null
    }
  ],
  "metrics": {"total": 1, "not_run": 1, "passed": 0, "failed": 0, "blocked": 0}
}
```

Если групп нет: `projects`, `users`, `checks` — пустые массивы; `project_id` и `project_role` — `null`; метрики нулевые. Если параметр `project` указан для чужой группы, возвращается `403`.

`user.role` — тип аккаунта `user` / `admin`. `project_role` и роли списка участников — `member` / `admin` для отображения; в текущих рабочих операциях права обоих типов одинаковы. Наличие участия обязательно для всех.

## Создание группы

`POST /api/projects`:

```json
{"name": "Моя группа"}
```

Название обязательно, до 100 символов. Ответ: `{"id": 3}`. Создавать может любой вошедший аккаунт. В одной транзакции сохраняются группа и участие создателя. Глобальная роль не меняется.

## Добавление участника

`POST /api/members`:

```json
{"project_id": 3, "email": "colleague@example.test"}
```

Вызывающий должен состоять в группе, добавляемый человек — уже зарегистрироваться. Повторное добавление и неизвестная почта отклоняются. Произвольную роль запрос не назначает. Ответ: `{"ok": true}`.

## Создание проверки

`POST /api/checks`:

```json
{
  "project_id": 3,
  "title": "Вход пользователя",
  "steps": "Ввести верные данные и нажать «Войти»",
  "expected": "Открылся обзор"
}
```

Все три текстовых поля обязательны. Название — до 200 символов; шаги и ожидаемый результат — до 5000. Ответ: `{"id": 8}`. Без сохранённого результата в состоянии проверки показывается `not_run`.

## Сохранение результата

`POST /api/checks/result`:

```json
{"project_id": 3, "check_id": 8, "status": "passed", "actual": "Обзор открылся"}
```

`status` — одно из `not_run`, `passed`, `failed`, `blocked`. `actual` — необязательная строка до 5000 символов; отсутствие означает пустой комментарий. Проверяется участие и принадлежность проверки указанной группе. Ответ: `{"ok": true}`.

Каждый запрос добавляет строку результата. Повторная отправка не является идемпотентной: появится ещё одна запись. Состояние показывает последнюю запись по `id`; специального механизма разрешения конфликтов версий нет.

## Выход

`POST /api/logout` с телом `{}` удаляет текущую сессию и очищает cookie. Ответ: `{"ok": true}`. Другие независимые сессии аккаунта остаются действующими.

## Ошибки

Тело ошибки: `{"error": "Понятное сообщение"}`.

| Код | Причина |
| --- | --- |
| `400` | Неправильные поля/статус, неизвестная почта, повторный участник, неподходящая проверка, неверное тело запроса. |
| `401` | Неверная почта или пароль при входе. |
| `403` | Нет сессии, нет участия в группе, неверный CSRF или Origin. |
| `404` | Неизвестный маршрут или действие. |
| `409` | Нарушена уникальность либо целостность SQLite, например повторная регистрация почты. |
| `429` | Слишком много неудачных входов. |

Список не означает, что все ошибки ОС и SQLite перехватываются: например, ошибка открытия файла или порта может завершить запуск. Такие случаи диагностируются по терминалу сервера.
