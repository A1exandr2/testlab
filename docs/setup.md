# Запуск и настройка

## Окружение

Приложение проверено с Python 3.13.7. Единственная сторонняя зависимость сервера — `bcrypt>=4.0,<6`. SQLite, HTTP-сервер и работа с JSON входят в стандартную библиотеку Python. Node.js не нужен для обычной работы приложения; проверки JavaScript и инструмент съёмки проверены на Node.js 24.

Команды ниже рассчитаны на Linux/macOS и выполняются из корня проекта. В Windows виртуальное окружение активируется командой `.venv\Scripts\activate`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python server.py
```

Откройте `http://127.0.0.1:8765`. Для остановки нажмите `Ctrl+C` в терминале сервера.

## Что происходит при запуске

1. Определяется путь файла базы.
2. `init_db()` выполняет `schema.sql`, создаёт недостающие таблицы и индексы.
3. При необходимости выполняются однократные переносы старых данных.
4. Создаётся демонстрационный аккаунт `admin@testlab.local` с паролем `Admin12345!`, если его ещё нет.
5. Создаётся стартовая «Общая группа», если она ещё не создана.
6. Сервер начинает принимать HTTP-запросы. Адрес выводится после успешного открытия порта.

Повторный запуск не создаёт дубликаты стартовых записей и не сбрасывает существующий пароль администратора. Проверки сохранности и повторной инициализации находятся в `test_workflow.py`.

## Параметры

| Настройка | По умолчанию | Как изменить |
| --- | --- | --- |
| Адрес прослушивания | `127.0.0.1` | `python server.py --host 127.0.0.1` |
| Порт | `8765` | `python server.py --port 9000` |
| Файл базы | `testlab.sqlite3` рядом с `server.py` | Переменная `TESTLAB_DB` |

Пример отдельной базы:

```bash
TESTLAB_DB=/tmp/testlab-demo.sqlite3 python server.py --port 9000
```

В этом случае адрес приложения — `http://127.0.0.1:9000`. Относительный путь в `TESTLAB_DB` считается от текущей рабочей папки; для однозначности удобно задавать абсолютный путь. По умолчанию база определяется относительно `server.py`, поэтому сервер можно запускать из другой папки.

Других переменных настройки сервер не читает. `.env` автоматически не загружается. Почта и пароль стартового аккаунта заданы константами в `server.py` и используются только при его первоначальном создании.

## Доступ из сети

`127.0.0.1` доступен только на компьютере с сервером. `--host 0.0.0.0` меняет адрес прослушивания, но сам по себе не настраивает HTTPS, сетевой доступ или защиту размещения. Текущий проект подготовлен для локальной работы; ограничения описаны в [maintenance.md](maintenance.md).

## Частые проблемы

| Ситуация | Что проверить |
| --- | --- |
| `ERR_CONNECTION_REFUSED` | Сервер запущен, процесс не завершился, в адресе правильный порт. |
| Порт занят | Остановить прежний процесс либо выбрать другой `--port`. |
| Новый интерфейс, но старые запреты | Перезапустить Python-процесс: он держит код API в памяти, а статические файлы читает с диска. |
| `No module named bcrypt` | Активировать окружение и установить `requirements.txt`. |
| Нет доступа к группе | Пользователь должен быть добавлен в неё по почте. |
| `PermissionError: Operation not permitted` при создании сокета | Среда запуска запрещает локальный сервер. Запустить в обычном терминале ОС с разрешённым открытием локального порта. |
